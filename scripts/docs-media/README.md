# Docs media

The screenshots, GIFs and terminal recordings in `docs/media` are generated by
these scripts, so they can be re-captured whenever the UI or CLI changes.
None of them touch a real casm installation.

## Web client: screenshots and GIFs

`showcase-server.ts` starts two disposable casm servers in one process,
`studio` and its peer `buildbox`, with fake providers (Claude, Codex, OpenCode,
pi), tidy demo projects under `/tmp/demo`, scripted transcripts, limits and
schedules. Its providers answer the prompts the GIF scenes send with streamed
replies and tool calls; no model is called.

```sh
npm run build                                   # the web client the server serves
node scripts/docs-media/capture-web.ts          # every scene
node scripts/docs-media/capture-web.ts gif-queue
```

`capture-web.ts` starts a fresh showcase server per scene, drives the web
client with Playwright's Chromium, and writes PNGs (palette-optimized) and
GIFs (frames from screenshots, encoded by ffmpeg with a shared palette).
It needs `ffmpeg` on `PATH`; a static build in `~/.local/bin` works.
`SHOWCASE_PORT` (default 7497, also uses the next port) and `SHOWCASE_HOME`
(default `/tmp/demo`) move it.

## CLI: terminal recordings

`lab.sh up` starts a real two-host lab (`studio` on 7481, `worker` on 7482,
state in `$LAB`, default `/var/tmp/casm-lab`) with a demo project in
`/tmp/code/acme-api`. `record-cast.ts` types each scene's commands, records
their real output with real timings (long gaps shortened) as asciicast v2,
and renders animated SVG with `npx svg-term-cli`:

```sh
node scripts/docs-media/record-cast.ts            # every scene
node scripts/docs-media/record-cast.ts cli-peers
```

These agents are real and make model calls: the scenes use Claude Haiku and
count against your subscription. The `.cast` files are kept next to the SVGs;
play one with `asciinema play docs/media/cli-peers.cast`.

casm runs Claude Code, Codex, OpenCode and pi on the computers you already own, and lets you drive them from your phone, your laptop or a script. One small server per machine. No casm cloud, no account, no relay.

Node + SQLite in ~/.casm-ng no telemetry any private network

$ git clone https://github.com/michaloo/casm.git && cd casm
$ npm ci && npm run build
$ scripts/install.sh --skip-deps
$ casm serve           # 127.0.0.1:7373, state in ~/.casm-ng

Needs Node.js 24+ and a provider CLI you're already logged in to.

The deal

Everything casm does happens on hardware you control.

Runs on your machines

A Node server per machine, with its state in a SQLite file under ~/.casm-ng. No casm service to sign up for, and nothing that phones home.

Your subscriptions

casm drives the official Claude Code, Codex, OpenCode and pi CLIs and SDKs you already use. Your login, your plan, no API middleman.

Your network

Tailscale, Headscale, WireGuard, a LAN or a Cloudflare tunnel. casm only needs one reachable port and a token per device.

Your devices

A web app you install on iPhone, Mac or desktop, served by your own server. Recent chats stay readable offline; notifications use standard Web Push.

What stays on your machine

Inside the line is yours. Two kinds of traffic cross it.

Each server owns its projects, agents, queues, schedules and tokens. Your phone talks to one server; servers talk to their peers. Only model calls and push notifications go out.

stays on your network, every connection carries a token leaves your network: outbound HTTPS only
How it works

A server, its peers, and the clients you already carry.

Run a server on each machine

It owns that machine's projects and agents, keeps state in SQLite and installs as a systemd user unit or a launchd agent. It listens on loopback until you choose otherwise.

casm service install
casm token create phone

Connect the machines as peers

A server forwards requests to its peers, one hop. Peering forwards commands; it never copies files or sessions.

casm peer add worker ws://worker:7373 '<token>'
casm -H worker projects

Drive agents from anywhere you are

Open your server's address and add it to your Home Screen or Dock. Or script it: agents get the same CLI, so they can spawn and steer other agents.

casm run --project acme-api --provider claude \
  --name reviewer "Summarize src/orders.js"
What you get

Built for unattended work on your own hardware.

Four providers, one place

Claude Code and Codex on your subscriptions; OpenCode and pi with any model they support, including local ones.

Queue and steer

Messages queue in strict FIFO order while an agent works. Steer puts a message into the running turn instead.

Limit-aware

casm limits shows Claude's and Codex's windows. A message that hits a limit waits for the reset and goes then, across restarts.

Schedules

Cron, interval or one-time jobs that message an agent or start a new one. --every 30m, --at "in 2h".

Agents running agents

Every agent gets the CLI with its own identity, so it can start, message and wait for others, on this host or a peer.

Approvals on your phone

Permission requests and questions show up in the web app and the CLI. casm notify sends a push when work is done.

Offline reading

The sidebar and recent chats are kept on the device and stay readable without a connection. Sending waits for the server.

Files and previews

Open files your agents mention, with line links and rendered HTML, through short-lived signed links with no token in the URL.

Open protocol

JSON-RPC 2.0 over one WebSocket, with a JSON Schema in spec/protocol.json. Write your own client.

Self-hosting recipes

Bring the network you trust.

casm has no relay and no TLS of its own, on purpose. Pick a network, then point casm at it. The network guide walks through each option with a checklist.

easiest

Tailscale

Every device on one tailnet, works behind CGNAT, the phone app keeps push working.

HTTPS: tailscale serve in front of loopback.

fully yours

Headscale

The same Tailscale clients with a control server you run. Needs one public server.

HTTPS: your domain with DNS-01, or an internal CA.

nothing extra

WireGuard

A plain tunnel, phones join with a QR config. A public hub if you're behind CGNAT.

HTTPS: Caddy with DNS-01, or mkcert.

phone-first

Cloudflare Tunnel + Access

A public address with a login in front, before any request reaches casm.

HTTPS: Cloudflare terminates TLS.

One rule: never expose port 7373 directly to the internet. A token is all that stands between a request and a shell on your machine, so keep the port on a private network or behind an identity-aware proxy. casm listens on 127.0.0.1 until you say otherwise.

What leaves your machine

Self-hosted doesn't mean nothing goes out. Here's exactly what does.

DataWhere it livesWho else sees it
Projects, agents, queues, schedules, tokensyour server SQLite in ~/.casm-ngNobody. casm has no cloud service and no telemetry.
Transcripts and filesyour server provider-native history on that machineYour devices, over your network. Peers forward requests; they don't copy sessions or files.
Prompts and code sent to a modelmodel providerAnthropic, OpenAI or whichever provider you configure, through its own CLI and your account. Not casm. With local models in OpenCode or pi, nothing leaves.
Notificationsbrowser push serviceApple, Google, Mozilla or Microsoft relay the message, encrypted so only your device can read it, and signed with VAPID keys your server generated itself. Off until you enable it per device.
Who can connectyour networkThe coordination server of your VPN, if you use a hosted one (Tailscale, Cloudflare). Self-host Headscale or WireGuard to remove it.

The provider CLIs casm drives are their own programs with their own update checks and telemetry settings; casm doesn't add to them or route around them. The web app's fonts and assets are served by your casm server, not a CDN.

FAQ

Questions people ask first.

Do I need an account with casm?

No. There's no casm account, cloud or relay. You install the server from the repository and create tokens for your own devices.

Does it use my Claude or ChatGPT subscription?

Yes. casm drives the official Claude Code (through Anthropic's Agent SDK) and Codex CLIs, logged in the way you already use them. It shows their usage windows and waits out limits instead of failing.

Can I use local models?

OpenCode and pi list the models in their own config, including local servers such as llama.cpp. Claude Code can point at an Anthropic-compatible local endpoint per agent.

Is it safe to reach from my phone?

Yes, over a private network: every connection needs a token, the browser sends it inside the connection rather than in a URL, and tokens can be revoked one by one. Don't put port 7373 on the public internet.

Does casm sandbox my agents?

No. Agents run as your user with their provider's own permission settings. casm passes their permission requests and questions to you. pi has no permission system, so its tools run without asking.

Does it sync files between machines?

No. Each server keeps its own projects. Peering forwards commands so you can drive agents on another machine; it doesn't copy files or sessions.

Do I need HTTPS?

Not to use it. The web app, Home Screen install on iPhone and the offline copy all work over plain HTTP on a private network. Notifications, a cold start with no connection and the Chrome/Edge install button need HTTPS with a certificate your device trusts.

Is there a native app?

The installable web app is the main mobile and desktop client. Native macOS and iOS clients are in progress on a separate branch.
